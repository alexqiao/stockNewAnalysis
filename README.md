# 股票事件研究平台

一个覆盖 A 股、港股和美股的本地研究工具。系统将多篇新闻先聚合为市场事件，再推导产业链主题和候选股票，最后把多个事件汇总为股票的 1、5、20 个交易日综合研判。

> 新闻是证据，不是结论。系统仅供研究与教育使用，不执行交易，也不承诺涨停或收益。

## 核心链路

~~~text
新闻 / X 主张 → 官方事实核验 → 1/5/20 日事件判断 → 量价与仓位约束 → 行动记录与结果验证
~~~

- 新闻通过 URL 指纹、中文/英文标题相似度和 72 小时时间窗聚合为事件。
- 模型第一阶段提取需求变化、主题、产业链角色和候选公司。
- 候选必须与证券主数据唯一匹配；无法验证的公司只显示为“待核实”，不进入排名。
- 模型第二阶段评估财务传导和八个研究维度，代码计算透明的 0–100 弹性分。
- 同一事件只贡献一次；多来源报道提高证据质量，不重复抬高股票信号。
- 股票页聚合同向和反向事件，并展示净方向、置信度与冲突度。
- 验证看板记录 Top-K 候选的超额收益、方向命中率和排序相关性。

## 如何看买入、持有和卖出判断

首页优先展示自选股行动，默认 **5 个交易日**，同时对照 1 日和 20 日。
自选股与证券详情 API、网页共用同一套确定性规则，不因打开页面新增大模型调用。

1. 在 `/watchlist` 填写“未持仓”或“已持仓”。`position` 表示自选顺序，
   `holding_status` 才表示持仓状态；未填写时不会判定执行条件齐备。
2. 打开 `/research`，刷新已有与官方来源，核对公司事件日历、财务事实、预期差与量价。
   在事件详情登记原始事实首次披露时间；新报道不能重置旧事实的短期有效期。
3. 在研究工作台查看自动填入的风险参数，再按需修改。实盘连接后的组合、股数和成本来自 IBKR。
   默认单股上限 20%、单股风险预算 1%、行业上限 40%、日均成交量参与上限 1%，
   单边手续费和滑点各按 10 基点估算；自动失效价取最近有效报价的 90%，随报价更新。
   手动设置优先且会保留；清空某项并保存恢复自动值。保存页面只提交修改项，不固定未修改的自动值。
   美股默认按整股测算，普通 A 股按 100 股；港股及特殊交易单位需已有证券资料或手动补充。
   行业仓位按完整券商快照及已有行业分类汇总；覆盖不完整时显示已识别部分并阻止数量测算，
   核对后可手动保存完整行业仓位。实际资金、数量、成本和未知汇率不使用假定值。
   已识别美股行业默认选择对应板块 ETF 作为近似基准，可手动替换；
   未识别行业不替换成宽基指数。默认 ETF 分类参照 [State Street 板块列表](https://www.ssga.com/us/en/individual/capabilities/equities/sector-investing/select-sector-etfs)。
   币种、交易日或复权口径不匹配时不计算行业超额收益。
4. 返回证券页看当前行动和具体阻断项。任务可保存完成、忽略及复核备注，来源变化时会重开。
   任务完成不等于已满足买卖条件；判断仍由实际数据重新计算。
5. 在 X 核验台账保存官方原文、支持或冲突证据及复核期限。转述同一原文不会重复计为独立证据。
6. 年度 PE 继续作为独立背景；旧规则折叠为对照。新规则不将年度估值差当成未来 5 日收益。

### 当前行动规则

首页和个股页的默认输出采用固定四段简报：**行动**（不超过 40 字）、**依据**（不超过 90 字）、
**下一步**（不超过 90 字）和**重评条件**（不超过 80 字）。简报只选一个最先可执行的缺口，
不会把所有来源、旧规则和待办一次性混在结论里；完整依据、风险参数和历史核验步骤放在“展开依据”中。
接口返回的 `judgment.strategy.execution.brief` 与页面使用同一份内容，方便前端保持一致。

| 情形 | 当前行动 |
| --- | --- |
| 正向事件，首次披露、行情与风险条件齐备 | 检查建仓 / 加仓条件，并展示风险预算约束下的股数上限 |
| 负向事件 | 未持仓暂不建仓；已持仓评估减仓 / 退出条件 |
| 已触及失效价，或当前仓位超预算 | 优先评估退出或减仓，利好不能覆盖已有风险约束 |
| 数据、持仓或证据不足 | 展示具体待补条件、原始出处、核实后的变化和复核时间 |

使用实际交易所日历和已收盘日线；未知价格、费用、持仓与复权口径不会补成零。
股数是约束条件下的上限，不是自动订单。首次采集旧数据不会伪装成当时已知的信息。

### 保留的旧规则对照

| 条件 | 未持仓 | 已持仓 |
| --- | --- | --- |
| 有效强多，估值位于或低于假设区间 | 买入候选 | 持有观察 |
| 有效强空，估值高于假设区间 | 暂不买入 | 卖出候选 |
| 有效强空，估值不高或估值数据不足 | 暂不买入 | 减仓候选 |
| 数据不足、过期、弱信号或证据冲突 | 等待 | 复核持仓 |

任一其他周期的有效强空信号会暂缓新增仓位；其他周期利好不会盖过已持仓的当前负面
风险。有效强信号的初始门槛为置信度至少 50%、决策分绝对值至少 20、冲突度低于 35%；
旧规则信号最多 1 个工作日、价格最多 3 个工作日，仍保留工作日近似以供对照。
新执行层使用 XNYS、XHKG、XSHG 交易日历核验，不把假期或未收盘日线当成新交易日。
已撤销或叙事化的证据不再支持行动，流水线会生成空证据的中性快照保留审计记录。
事件时间超过当前时间 5 分钟时也暂停作为当前信号依据，原始记录继续保留供核查。

这些门槛是**尚未回测校准的启发式规则**，置信度不是胜率，候选也不是自动下单指令。
年度 PE 估值情景不充当 5 日目标价或止损价。缺少真实持仓、资金或可靠行情时不计算股数。
行动判断单独检查已知持仓是否超过单股上限、行业上限、失效价或情景损失预算；
缺现金或完整行业资料不会隐藏其他已经能确认的风险，但仍阻止具体数量测算。
默认上限明确标为“默认”，结论以“若沿用当前参数”为前提，可在研究工作台修改。
失效价情景损失包含费用假设，不是实际亏损保证。沿用上次成功持仓快照并标明日期，发生交易后手动同步；空头不套用多头模型。
首页同时给出当前方向、事实依据、加仓和退出条件；1、5、20 日分别展示即时风险、催化和经营假设的复核重点，
不把不同周期的复核任务冒充不同的价格预测。
研究工作台按规则版本、市场和周期保存不可变行动快照，用后续实际交易日检验收益、行业超额、
收盘回撤与成本。重复证据去重，样本不足不输出校准概率；现有新闻信号验证看板继续保留。

常用接口：`GET /api/v1/watchlist?horizon=5`、
`GET /api/v1/securities/{id}?horizon=5`；返回 `judgment.action`、三个周期的 `judgments`、
`social` 和 `event_checks`。后续优化优先级见 [优化计划](OPTIMIZATION_PLAN.md)。

研究接口：`GET /api/v1/research/securities/{id}`、`POST /api/v1/research/refresh`、
`POST /api/v1/research/capture`、`GET /api/v1/research/calibration`。
刷新为后台任务；调度启用时启动 1 分钟后检查，之后默认每 6 小时更新，任务冲突会重试。
来源覆盖区展示自动刷新是否运行、下次计划和最近尝试时间。“待刷新”表示已到重新核对时间，
历史资料仍保留；“访问受限”表示 HTTP 401/403 拒绝请求，需按提示核对接口权限或网络出口。
Finnhub 各接口权限独立，财报日历可用不代表分红接口可用；BLS 访问被拒绝也不代表其他来源不可用。
通过 `RESEARCH_REFRESH_ENABLED` 和 `RESEARCH_REFRESH_INTERVAL_HOURS` 配置。
数据库升级前先备份，再执行 `uv run alembic upgrade head`。

## IBKR 真实持仓

在 `/watchlist` 的“真实持仓”区域连接本机 TWS / IB Gateway，选择一个实盘账户，
点击“同步真实持仓”。同步成功后，首页、自选和研究工作台统一读取券商快照。
股票和 ETF 自动加入自选，原自选的排序及风险预算、止损价等个人约束保留。
完整快照中已不持有的证券标为空仓；数量、成本、比例和组合资产不再接受手填覆盖。

安装官方 SDK（已验证 TWS Python API 10.45.1）：

~~~bash
uv sync --extra dev --extra ibkr
# 从 IBKR 官方 TWS API 下载包解压后，将下方路径换成其 source/pythonclient 目录。
uv pip install --python .venv/bin/python /path/to/IBJts/source/pythonclient
uv run --no-sync alembic upgrade head
uv run --no-sync trade-news serve
~~~

本机已存在 SDK 时，可以使用：

~~~bash
uv pip install --python .venv/bin/python ../TradeAnalysis/twsapi_macunix/IBJts/source/pythonclient
~~~

SDK 不从同名第三方 PyPI 包安装，也不作为项目代码分发。
`ibkr` 扩展固定 SDK 所需的 protobuf 版本；重新执行 `uv sync` 后需重新安装本地 SDK，
或用 `uv sync --inexact --extra ibkr` 保留它。未安装 SDK 时其他功能仍可使用。

连接前，在 TWS 设置中启用 Socket 客户端并勾选 **Read-Only API**。
默认连接 `127.0.0.1:7496`（TWS 实盘），可选 `4001`（Gateway 实盘）或自定义端口；
Client ID 默认 `72`，须与其他应用不同。仅接受当前连接实际返回的实盘账户。
不需要提供或保存账号密码；数据库记录脱敏账户标识，客户端不包含交易操作。

- 只在点击按钮时同步，不后台轮询。连接和同步互斥，应用保持单 worker 运行。
- 快照、持仓和自选状态在同一事务提交；断线、超时、账户未就绪及证券匹配冲突均保留旧数据。
- 最近同步失败或快照超过 24 小时，继续沿用上次成功快照并标明日期，资金和仓位按该快照估算；重启后未完成的同步标为失败。
- 股票以合约、市场、代码和币种匹配；期权、债券及其他未支持资产留在明细中，不套用股票模型。
  空头保留真实数量和状态，并停止多头行动与数量测算。
- 市值和成本保留原币，净值使用账户基础币种。持仓比例使用同次快照的 IBKR 汇率，
  兼容 `$LEDGER-ExchangeRate` 字段；缺行情、净值或汇率时保持未知。
- 非融资资金上限为同币种 `max(0, min(SettledCash, AvailableFunds))`。
  `SettledCash` 未返回时保持未知，不以现金余额或购买力替代；例如 `SettledCashByDate`
  不能直接当作该数值。跨币种数量测算仍沿用现有阻塞规则。

接口：`GET /api/v1/holdings` 查看快照；`POST /api/v1/holdings/ibkr/accounts`
传入 `port`、`client_id` 读取脱敏账户列表；`POST /api/v1/holdings/ibkr/sync`
再传入列表返回的 `account_key` 执行同步。同步冲突返回 409，券商连接失败返回 503。
页面及 API 包含真实财务数据，仅在受信任的本机环境访问。

## 美股与港股日 K 线

打开股票详情页的“日 K 线”，可查看最近五年的已收盘日线、成交量、MA5/10/20/60
和布林带 BOLL(20,2)，其中标准差采用总体标准差。
默认显示一年，支持 3 月、6 月、1 年、3 年和 5 年区间、缩放、拖动及十字光标。
红色表示上涨，绿色表示下跌；成交量以股为单位，缺失时保持未知。
均线按当前选择的价格口径计算，切换区间、均线或复权无需重新请求数据源。

日线由 Yahoo/yfinance 免费获取，独立保存到本地数据库，不要求 Tushare Token。
默认使用“含分红调整价格”，也可切换为“拆股调整价格”；后者仍包含 Yahoo 的拆股调整，
不是历史实际未复权成交价。缺少有效复权数据时仅显示基础价格，并在页面提示。
价格不作跨币种换算，来源币种与证券不一致时保留旧数据并报告失败。
图表使用本地打包的 TradingView Lightweight Charts，许可及署名见
[第三方说明](THIRD_PARTY_NOTICES.md)。

- 新增或重新启用美港自选股、成功同步持仓后，后台补齐行情；其他证券首次打开详情时按需获取。
- 首次补最近五年，新上市股票按实际历史展示。自选和持仓每 15 分钟检查一次，
  仅更新已到交易所实际收盘后 60 分钟的交易日；需应用保持运行且启用调度器。
- 平时回查最近 10 个交易日；发现分红、拆股或历史口径修订时重取完整保存区间，
  每七天再完整校正一次。节假日、停牌及缺失数据不会补造蜡烛。
- 刷新失败或被限流时保留旧图，分别显示最新交易日与最近成功抓取时间。
  失败按 15 分钟、1 小时、6 小时退避；服务重启后补漏。
- `DAILY_BARS_ENABLED=false` 关闭自选/持仓触发及定时更新，图表按需获取和手动刷新仍可用。
  `SCHEDULER_ENABLED=false` 关闭定时检查。日线使用独立后台队列，不等待新闻分析；
  同一证券的重复请求合并，页面在当前股票完成后即可展示，无需等待整批股票。

只读接口 `GET /api/v1/securities/{id}/daily-bars` 返回基础及复权 OHLC、成交量、
覆盖范围、来源和同步状态，可用 `start=YYYY-MM-DD&end=YYYY-MM-DD` 按交易日期筛选
（两端均包含）。`POST /api/v1/securities/{id}/daily-bars/refresh` 返回后台 `run_id`，
通过 `GET /api/v1/runs/{run_id}` 查询进度；`?force=true` 可主动刷新，但仍遵守限流冷却。
GET 不触发采集；页面有缺口时另行 POST。现有研究快照与行动判断继续使用原接口。

升级前备份数据库，再执行 `uv run --no-sync alembic upgrade head` 并重启服务。
Yahoo 数据用于个人研究，供应商接口可能限流或变更；使用范围遵循
[yfinance 项目说明](https://github.com/ranaroussi/yfinance)。

### 布林带操作参考

K 线下方按完整本地历史识别缩口、向上突破及首次回踩，不随可见时间区间截断历史。
默认要求首次回踩前已知中轨向上，并满足跳空、收敛或缩量条件之一；
第一次回踩不合格即结束该轮候选，不将之后的回踩重新算作第一次。
参数可在面板中修改、恢复默认，并保存在当前浏览器；这些阈值是可解释的研究假设，
未经收益回测验证。固定 BOLL(20,2)，跟随图表复权口径；缺失复权时整段使用基础价格。
下轨方向默认比较最近 5 根已收盘日线的下轨，变化达到 +0.5% 为上行、
达到 -0.5% 为下行、其余为走平；周期和门槛可调。下轨方向列入加仓待核对条件，
不把下轨上行单独当作买点，也不因下轨走平对已有持仓自动生成卖出指令。

初始止损参考突破前已确认的摆动低点与下轨；较大浮盈后，显示第二档已确认支撑
对应的追踪止损参考，且不低于明确保存的止损。默认估算止损不会冒充已记录止损。
行情过期、空头、持仓矛盾及已知风险超限会暂停当前建议，但保留技术形态；持仓继续沿用上次成功快照并标明日期。
历史有拆股但保存止损缺少独立口径确认记录时，只展示原始输入，不自动判断其触发或上移。
均为收盘后条件参考，不能确认盘中先后顺序或实际成交，复权参考价不能直接作委托价。

首版不生成加仓指令或推断已成交批次，只列出待满足条件；20%/20%/20%/40%
指本轮事先确定的计划仓位比例。技术参考与新闻/估值综合判断分别展示，不改写已有
行动快照，也不写入止损或执行交易。只读接口
`GET /api/v1/securities/{id}/bollinger-reference` 支持 `adjustment` 及面板中的参数，
重算只读取本地缓存，不调用行情供应商。

## 数据源与降级

- 配置 TUSHARE_TOKEN 时，优先同步 A/港/美股证券主数据和日线行情。
- Tushare 返回限频后，同一进程按凭据与接口共享冷却时间；美股个股和 SPY 共用 `us_daily` 限额。按响应中的分钟/小时窗口暂停请求，冷却期间港美股直接使用已有 Yahoo 回退，到期再尝试。仅首次触发记录警告；回退不保证数据完整，仍校验原始行情日期和复权口径。
- 研究行情默认只刷新活跃自选股；同轮股票与行业基准共用请求结果，失败也去重。下一轮重新请求，不把缓存读取时间当作新的行情时间。
- TUSHARE_NEWS_ENABLED=true 仅应在账户具备新闻权限时启用。
- 安装 data 扩展后，可在无 Token 时用 AKShare 补充 A 股证券列表和宽口径财经新闻。

## X/Twitter 博主动态

系统每 6 小时采集白名单博主的可见帖子，只保留最近 24 小时的原创和引用帖。
默认优先使用独立的本地 Chrome 配置，浏览器失败时尝试读取 X 公开主页。
公开主页只展示部分帖子（可能包含旧置顶帖），不能保证覆盖完整 24 小时；界面会显示
覆盖缺口。全部帖子先进入“博主动态”收件箱；个人观点、预测和传闻默认不进入事件评分，
只有官方/媒体事实或人工确认的线索才会成为事件证据。

个人观点和预测现在也会出现在自选股与证券页的“X 博主线索”中：优先按明确公司实体
关联，再按事件或明确产业主题关联；主题背景不会被当作个股方向。直接观点按作者最新
有效单股表述去重，展示多空分歧、原帖、待验证事项和审核入口，不因帖子数量或热度直接
增加正式分数。人工纳入的帖子仍沿用原有事件证据流程，避免重复计分。

收件箱与证券页会显示自动采集是否启用、近期成功账号数和失败/陈旧缺口。没有帖子且
采集失败，不会被描述为“博主没有观点”。临时模型失败的帖子再次采到时会重试筛选；
已成功筛选及人工处理的帖子不会重跑。实体提取不完整的帖子仍需在收件箱人工核验。

使用浏览器模式时，先安装正式版 Google Chrome，再安装浏览器采集扩展：

~~~bash
uv sync --extra dev --extra data --extra social
uv run trade-news x-login
~~~

首次登录会通过 Playwright 启动系统安装的正式 Google Chrome。程序只复用保存在
`./data/x-browser-profile` 的浏览器会话，不保存 X 用户名或密码。确认登录后启用调度：

~~~dotenv
X_BROWSER_ENABLED=true
X_FETCH_MODE=auto
X_BROWSER_HEADLESS=true
X_FETCH_INTERVAL_HOURS=6
X_LOOKBACK_HOURS=24
X_BROWSER_PROFILE_PATH=./data/x-browser-profile
# 未设置时自动使用系统 / 环境代理；也可显式指定
# X_BROWSER_PROXY_URL=http://127.0.0.1:1082
~~~

重启服务后可在 `/x/accounts` 维护账号，在 `/x` 查看和审核帖子。也可以手动执行：

~~~bash
uv run trade-news x-ingest
~~~

X 抓取使用独立工作线程，新闻采集或模型分析繁忙时仍可启动。每个账号的原帖先保存到
收件箱，再由原有分析队列进行模型筛选；页面会区分“正在抓取”“已入库、等待筛选”和
处理完成。抓取完成后页面自动刷新，待筛选内容也可直接查看。启用自动采集后，服务启动
约 1 分钟会执行首次 X 抓取，之后按配置间隔执行。

若本机的无头浏览器访问不稳定，而公开主页可正常返回帖子，可设置 `X_FETCH_MODE=public`
直接请求主页。该方式只覆盖主页返回的可见帖子，可能缺少更早内容、完整长帖或登录后内容；
运行状态仍标记为 `public_page`，不代表完整时间线。

`X_FETCH_MODE` 可选 `auto`（默认）、`browser`、`public`。`auto` 在浏览器失败后尝试
公开页面；登录、代理配置或浏览器启动故障发生后，本轮其余账号直接尝试公开页面，下轮会
重试浏览器。单个账号的网络或页面失败不影响后续账号继续尝试浏览器。跳过浏览器时仍保留
最初的故障原因；若公开页面也失败，运行状态会同时显示两条通路的错误。
主页明确显示 `Account suspended` 时会直接报告账号已停用，不再提示切换浏览器模式；
该账号失败不会阻止其他账号采集。账号恢复前，可在 `/x/accounts` 停用其采集。
`public` 不需要登录，仅读取公开主页可见内容；`browser` 只使用登录浏览器。
公开页面通路支持 HTTP/HTTPS 代理；SOCKS5 代理需使用浏览器模式。代理凭据不会出现在错误提示中。

新版页面没有 `data-testid` / `<time>` 时，系统使用帖子链接识别文章并从 X Snowflake ID
恢复发布时间。截断长帖或订阅摘要标记为“正文未完整”，筛选后保持待审核，不自动纳入事件。
媒体文件只保存原始链接，不下载或解读图片和视频。

全部账号失败时，`x-ingest` 会返回非零退出码；部分失败保留已成功采集的帖子，各账号错误
显示在运行状态页。定时 X 采集遇到上一轮 X 任务未结束时，1 分钟后重试。
遇到 `net::ERR_HTTP_RESPONSE_CODE_FAILURE` 时先确认系统代理可访问
X；必要时设置 `X_BROWSER_PROXY_URL`。浏览器模式登录失效时再执行 `x-login`。

## 评分与验证

研究分由需求确定性 20、财务传导 20、业务纯度 15、规模弹性 15、市场忽视 10、新颖度与未定价 10、证据质量 5、验证速度 5 组成，并扣除最多 20 分风险项。证据质量按来源等级和独立性计算：公告、监管文件和官方披露高于权威媒体，普通转载和社交线索只作为弱证据。公司缺少主营业务、市值或行业资料时，相关维度会被确定性封顶。

股票综合信号按事件方向、研究分、模型置信度和时间衰减聚合为决策分。1、5、20 日信号分别以相同交易日数作为半衰期，超过三个周期后退出；正反事件同时存在时冲突度上升。低于最低置信门槛的结论保留为研究记录，但不进入多空榜。排名在每个市场和方向内独立计算。

模型会把需求状态标记为 `observed`、`inferred` 或 `narrative_only`。纯叙事事件保留主题、候选和待验证证据，但不会生成当前股票信号。常见主题同义词在入库时映射到保守的标准主题；不同经济环节不会仅凭文本相似度强行合并。

前向验证从信号生成后所在交易所的首次可交易开盘开始，使用真实交易日和半日市时刻。
预期入场日或窗口中缺失历史行情时保持待验证，不把后来行情当成旧信号的入场价；
只有明确为零成交量的停牌日才跳过。新结果标为 `strict-sessions-v2`，已有结果保留
`legacy-v1`，分别统计，不改写历史记录。除方向命中率和平均超额收益外，
看板只统计新版决策分快照。同一证券、周期和实际入场日只保留入场前最后一个信号，
并按市场、周期和实际入场日计算完整证券横截面的 Spearman Rank IC，汇总未年化
Rank ICIR；少于三个有效证券的横截面不参与计算。旧快照继续保留用于审计，但不混入
新口径指标。逻辑基准为：

- A 股：CN_CSI300
- 港股：HK_HSI
- 美股：US_SPY

具体行情代码由数据适配器转换。A 股只有数据源提供每日涨停价时才记录“触及涨停”，系统不估计涨停概率。

行动快照的主动作与去重键统一使用新版执行结论，记录口径为 `execution-actions-v2`；
没有该标记的历史快照按 `legacy-v1` 独立展示。事件方向命中率不等于减仓或退出行动的胜率。

~~~

## 数据边界

- 默认只保存标题、摘要、来源、链接和必要元数据，不下载新闻全文。
- 模型提出的公司必须经过本地证券主数据解析，无法唯一匹配的候选不会进入排名。
- 历史信号以快照持久化，避免用后来出现的新闻重写过去预测。
- 样本不足 30 条时，看板明确标记“证据不足”。
- yfinance 与 AKShare 的免费接口仅适合研究用途；商业使用前必须确认数据授权和供应商条款。
